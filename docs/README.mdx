## Product Documentation

Product documentation for the toolkit is available at
[https://docs.nvidia.com/nemo/guardrails](https://docs.nvidia.com/nemo/guardrails).

## Building the Documentation

1. Make sure Node.js 22 is installed.

1. Install the documentation script dependencies:

   ```console
   npm ci
   ```

1. Build the documentation:

   ```console
   make docs-fern
   ```

   The Fern docs configuration is validated with the pinned Fern CLI.

## Live Documentation Server

For local development with automatic rebuilding on file changes, use one of the following methods:

### Option 1: Local Fern Server

```bash
make docs-fern-live
```

The local server reuses existing generated Python SDK pages. Run
`make docs-fern-generate-sdk` when you need to force reference regeneration.

The Fern development server starts locally and updates as you edit docs files.

### Option 2: Published Branch Preview

```bash
make docs-fern-preview-watch
```

This watches local docs and Fern configuration changes and publishes a preview for the current Git branch.

### Option 3: Direct Fern Command

```bash
cd fern
npx --yes fern-api@$(node -p "require('./fern.config.json').version") docs dev
```

Once the server is running:

- Open the local URL printed by Fern
- Edit documentation files or Fern configuration
- Save the file
- The browser will automatically refresh with the updated content

Press `Ctrl+C` to stop the server.

## Publishing the Documentation

Stable library tags starting with `v0.24.0` create frozen documentation
versions automatically. The publish workflow exports the tagged `docs/`
content and embedded example files, generates a version-specific navigation
file, and publishes the result with the current `Latest` documentation.

Use a `docs-v<semver>` tag to republish the site without adding a new version.
Prerelease tags do not create documentation versions.

Each release snapshot freezes the authored guides, assets, components, files
embedded with `<Code src="...">`, Python package source, and OpenAPI
definition from the same tag. Publishing regenerates that version's Python SDK
reference from the archived package and routes its API reference to the
archived OpenAPI definition.

### Preview Versioning Locally

Before the first automated tag exists, materialize the current checkout as a
temporary `v0.24.0` snapshot:

```console
npm run docs:versions -- --preview-version v0.24.0
make docs-fern-live
```

Generating a materialized version's Python SDK reference uses Fern's local
source parser and requires a running Docker daemon.

After you stop the server, remove the generated snapshot and restore the
generated entries in `fern/docs.yml` and `fern/generators.yml`:

```console
npm run docs:versions:clean
```

The release snapshot and version navigation are ignored build artifacts. Do
not commit `fern/generated/` or generated `fern/versions/v*.yml` files.
