# Overview

The NeMo Guardrails toolkit is an open-source package for adding programmable guardrails to LLM-based conversational applications.
Guardrails (or "rails" for short) are specific ways of controlling the output of a large language model, such as not talking about politics, responding in a particular way to specific user requests, following a predefined dialog path, using a particular language style, extracting structured data, and more.

The following diagram is a simplified view of the programmable guardrails flow between the application, application user, and the guardrails system. Guardrails simply acts as a filter between the application and the user.

```{image} ../_static/images/programmable_guardrails.png
:alt: "Programmable Guardrails"
:width: 800px
:align: center
```

The toolkit supports five main categories of rails that work together to provide comprehensive protection.

| **Rail Type**        | **Description** |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Input rails**      | Applied to the input from the user. An input rail can reject the input, stopping any additional processing, or alter the input (for example, to mask potentially sensitive data or to rephrase).                            |
| **Dialog rails**     | Influence how the dialog evolves and how the LLM is prompted. Dialog rails operate on canonical form messages and determine if an action should be executed, if the LLM should be invoked to generate the next step or a response, or if a predefined response should be used instead. |
| **Retrieval rails**  | Applied to the retrieved chunks in the case of a RAG (Retrieval Augmented Generation) scenario. A retrieval rail can reject a chunk, preventing it from being used to prompt the LLM, or alter the relevant chunks (for example, to mask potentially sensitive data). |
| **Execution rails**  | Applied to input and output of the custom actions (or tools) that need to be called.                                                                                                                                        |
| **Output rails**     | Applied to the output generated by the LLM. An output rail can reject the output, preventing it from being returned to the user, or alter it (for example, removing sensitive data).                                         |

To each rails, you can attach guardrail LLMs to perform the guardrail checks.

## Benefits

Adding programmable guardrails to your LLM-based applications provides the following key benefits:

| **Benefit**                                             | **Description**                                                                                                                                                                                                            |
|---------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Building Trustworthy, Safe, and Secure Applications     | Define rails to guide and safeguard conversations. Specify allowed or disallowed topics to control application behavior and prevent engagement in unwanted discussions.                                                    |
| Connecting Models, Chains, and Services Securely        | Seamlessly and securely connect an LLM to other services or tools.                                                                                                                  |
| Controllable Dialog                                     | Steer the LLM to follow predefined conversational paths, supporting best practices for conversation design and enforcing standard operating procedures (such as authentication and support).                                |
| Protection Against LLM Vulnerabilities                  | Provides mechanisms to protect LLM-powered applications against common vulnerabilities, including jailbreaks and prompt injections.                                                  |

## Tools

The NeMo Guardrails toolkit provides two main interfaces for adding guardrails to your applications:

### SDK

The Python SDK is the primary way to integrate guardrails into your application.
Using the SDK requires only minimal changes to your code base and involves two simple steps:

1. Load a guardrails configuration and create an `LLMRails` instance.
2. Make the calls to the LLM using the `generate` or `generate_async` methods.

```python
from nemoguardrails import LLMRails, RailsConfig

# Load a guardrails configuration from the specified path.
config = RailsConfig.from_path("PATH/TO/CONFIG")
rails = LLMRails(config)

completion = rails.generate(
    messages=[{"role": "user", "content": "Hello world!"}]
)
```

The input and output format for the `generate` method is similar to the [Chat Completions API](https://platform.openai.com/docs/guides/gpt/chat-completions-api) from OpenAI.

For more information, refer to the [Python API Guide](user-guides/python-api.md) and [Getting Started](getting-started.md).

### CLI

The NeMo Guardrails toolkit provides a command-line interface for interacting with your guardrails configurations:

```bash
$ nemoguardrails --help

Usage: nemoguardrails [OPTIONS] COMMAND [ARGS]...

actions-server    Start a NeMo Guardrails actions server.
chat              Start an interactive chat session.
evaluate          Run an evaluation task.
server            Start a NeMo Guardrails server.
```

**Guardrails Server**:
You can use the NeMo Guardrails toolkit CLI to start a guardrails server.
The server can load one or more configurations from the specified folder and expose an HTTP API for using them.

```bash
nemoguardrails server [--config PATH/TO/CONFIGS] [--port PORT]
```

For more information, refer to the [CLI Guide](user-guides/cli.md) and [Server Guide](user-guides/server-guide.md).

## Relation with NeMo Guardrails Microservice

The NeMo Guardrails toolkit is an open-source SDK and runtime for adding programmable guardrails to LLM applications.
It provides the core framework, built-in guardrails library, and integration capabilities described in this documentation.

The **NeMo Guardrails Microservice** is a managed, production-ready deployment option that packages the NeMo Guardrails toolkit as a scalable microservice within the broader NeMo Microservices ecosystem.

|                        | **NeMo Guardrails (SDK/Toolkit)**                       | **NeMo Guardrails Microservice**                       |
|------------------------|---------------------------------------------------------|--------------------------------------------------------|
| Availability           | Open-source toolkit for developers                      | Enterprise-ready managed service                       |
| Installation/Packaging | Installed via pip (`pip install nemoguardrails`)        | Packaged as a containerized microservice               |
| Integration            | Flexible integration into any Python application        | Integrated with NeMo Microservices Helm Chart for Kubernetes deployment |
| Deployment/Scaling     | Self-managed deployment and scaling                     | Managed scaling, monitoring, and operations            |
| Customization          | Direct access to all features and customization options | Part of the NVIDIA AI Enterprise software suite        |

Both share the same core guardrails capabilities and configuration format.
Guardrails configurations developed with the open-source toolkit can be deployed using the microservice, and vice versa.

For information about deploying the NeMo Guardrails toolkit in production environments, refer to the [Server Guide](user-guides/server-guide.md) and [Using Docker](user-guides/advanced/using-docker.md) documentation.
