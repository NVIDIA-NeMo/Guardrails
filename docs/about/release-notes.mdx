<a id="v0-25-0"></a>
## 0.25.0

Version 0.25.0 expands input, output, and tool checks. It also changes Python
requirements and deprecates the `LLMRails` engine and Colang runtimes.

<a id="v0-25-0-features"></a>
### Key Features

New integrations and rails extend checks to model requests, tool calls, and languages.

- The experimental [NeMo Guardrails Gateway](/run-guardrailed-inference/using-gateway)
  applies input and output rails to supported OpenAI Chat Completions and
  Responses requests. It inspects one user text input and one assistant text
  output and supports both buffered and streaming responses.
- The [hooks server](/run-guardrailed-inference/using-hooks-server/overview)
  checks tool calls before Claude Code, Codex, or NeMo Relay executes them.
  You can allow or block tools by name and check their arguments before execution.
- With `IORails`, you can run [per-tool checks](/configure-guardrails/guardrail-catalog/tool-calling)
  on arguments and results using regular expressions, Common Expression Language
  (CEL) expressions, or a large language model (LLM) judge.
- The `/v1/checks` endpoint can run per-tool checks independently of generation.
  It reports which tools violated a policy in `tool_violations`.
- The [Language Detector](/configure-guardrails/guardrail-catalog/language-detector)
  input rail can allow or block messages by language and return a localized
  refusal.
- The library restores input and output moderation with
  [Zscaler AI Guard](/configure-guardrails/guardrail-catalog/third-party/zscaler-aiguard).

<a id="v0-25-0-breaking-changes"></a>
### Breaking Changes

Existing applications can require environment, streaming, or error-handling updates.

- **Python support.** Upgrade Python 3.10 environments to Python 3.11, 3.12,
  or 3.13 before installing this release. Refer to [Installation](/get-started/installation-guide).
- **Event-loop patching.** If your application enables automatic event-loop
  patching, install `nemoguardrails[nest-asyncio]`. In an application or
  notebook with a running event loop, you can use `await rails.generate_async(...)`.
- **Streaming tool calls.** Python consumers of `IORails` streams now receive
  completed tool calls as `ToolCallChunk` objects. To update a stream consumer:

  1. Read completed calls from `chunk.tool_calls`.
  1. Handle text chunks separately.
- **Jailbreak detection.** The model-based rail rejects messages longer than
  2,048 tokens, including special tokens. If a detector is unavailable or returns
  an invalid result, the request stops with an internal error. To update an
  application that uses this rail:

  1. Keep each message within the token limit.
  1. Ensure the `tokenizers` package is installed for input validation.
  1. Enforce blocked results when using check-only APIs.

  Refer to [Jailbreak Protection](/configure-guardrails/guardrail-catalog/jailbreak-protection).

<a id="v0-25-0-deprecations"></a>
### Deprecations

The following engines, runtimes, and configuration names remain available but are deprecated.

- The `LLMRails` engine and the Colang 1.0 and 2.x runtimes are deprecated.
  Removal is planned no earlier than 0.27.0. Before migrating:

  1. Review engine coverage in [Migrating to 0.25](/reference/0-25), especially
     for dialog flows or a Colang 2.x application.
  1. Use `Guardrails(config)` to run supported configurations on `IORails`.

- The `tool_output` and `tool_input` names remain available as deprecated aliases.
  To update rail configuration and generation options:

  1. Rename `tool_output` to `tool_call`.
  1. Rename `tool_input` to `tool_result`.

<a id="v0-25-0-fixes"></a>
### Fixes and Enhancements

Streaming errors, injection handling, and configuration validation have the following updates.

- When the API server encounters a rail execution failure during streaming,
  it sends a terminal server-sent error event. Clients can distinguish a failed
  check from a completed response.
- Injection detection rechecks the text after removing a match and blocks the
  request if it cannot safely remove all matches.
- Configuration loading validates model references in global and per-tool rails.
- Configuration loading suggests supported names when it encounters an unknown
  configuration key.
