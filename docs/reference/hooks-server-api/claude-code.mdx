```text
POST http://localhost:8100/v1/hooks/claude-code
```

Checks the tool call in a Claude Code `PreToolUse` hook input, and answers in Claude Code's hook output format.
The hooks server applies its tool policy, then the called tool's per-tool rails.
An allowed call gets an empty object, so Claude Code continues with its own permission flow; a denied call gets a deny decision with the reason.
A check that cannot finish returns an error status, which Claude Code treats as a failed hook.

The request examples come from the [Claude Code example configuration](https://github.com/NVIDIA-NeMo/Guardrails/tree/develop/examples/configs/agent_hooks/claude_code).
For setting up the hook, refer to [Check Claude Code Tool Calls with the Hooks Server](/run-guardrailed-inference/using-hooks-server/claude-code).

## Request

This endpoint expects an object: Claude Code's `PreToolUse` hook input.
The server reads the following fields, and accepts and ignores every other field Claude Code sends, such as `session_id`, `cwd`, and `permission_mode`.

<ParamField path="hook_event_name" type="string" required={true}>
The hook event, `PreToolUse`.
Any other event returns `422` with the code `unsupported_hook_event`.
</ParamField>

<ParamField path="tool_name" type="string" required={true}>
The tool Claude Code is about to call, such as `Bash`, `Read`, or `mcp__<server>__<tool>`.
The tool policy and per-tool rails match it exactly. Must not be empty.
</ParamField>

<ParamField path="tool_input" type="any" required={true}>
The tool call's arguments.
A value that is not a JSON object is denied.
</ParamField>

<ParamField path="tool_use_id" type="string" required={true}>
Claude Code's ID for the tool call, which the server logs.
</ParamField>

## Response

An allowed call returns `200` with an empty object, `{}`, which carries no decision.
A denied call returns `200` with the following object.

<ParamField path="hookSpecificOutput" type="object" required={true}>
The deny decision.
</ParamField>

<ParamField path="hookSpecificOutput.hookEventName" type="string" required={true}>
Always `PreToolUse`.
</ParamField>

<ParamField path="hookSpecificOutput.permissionDecision" type="string" required={true}>
Always `deny`. The server never returns `allow`, which would skip Claude Code's permission prompt.
</ParamField>

<ParamField path="hookSpecificOutput.permissionDecisionReason" type="string" required={true}>
Why the call was denied, prefixed with `NeMo Guardrails: `.
The reason is the tool policy's reason, such as `tool call 'TodoWrite' is not an allowed tool`, or the name of the per-tool rail that blocked the call.
For the reasons, refer to [Deny Reasons](/run-guardrailed-inference/using-hooks-server/results-and-errors#deny-reasons).
</ParamField>

## Errors

Every error uses the OpenAI error envelope, with `message`, `type`, `param`, and `code` in an `error` object.
The endpoint can return the following errors:

| Status | `code` | When |
|---|---|---|
| `422` | `unsupported_hook_event` | `hook_event_name` is an event other than `PreToolUse`. |
| `422` | `null` | The body is not JSON, or is not a JSON object. `param` is `null`. |
| `422` | `null` | A required field is missing or invalid. `param` names the field. |
| `500` | `rail_failed` | A per-tool rail failed instead of deciding, for example because its model call failed. |
| `500` | `null` | The check failed for another reason, or the server hit an unexpected error. |
| `503` | `queue_full` | The server's admission queue is full. The response carries `Retry-After: 30`. |

For every error, refer to [Hooks Server Results and Errors](/run-guardrailed-inference/using-hooks-server/results-and-errors#errors).
