```text
POST http://localhost:8100/v1/hooks/nemo-relay
```

Checks the tool call that a NeMo Relay plugin's tool conditional-execution guardrail forwards, and answers with a decision.
The hooks server applies its tool policy, then the called tool's per-tool rails.
The plugin returns the decision as its guardrail callback's result: `Ok(None)` for an allow, `Ok(Some(reason))` for a deny, and `Err` for any error status, timeout, or failed connection.

The request examples come from the [NeMo Relay example configuration](https://github.com/NVIDIA-NeMo/Guardrails/tree/develop/examples/configs/agent_hooks/nemo_relay), which allows a `search` tool with only a `query` argument.
For the plugin side, refer to [Check NeMo Relay Tool Calls with the Hooks Server](/run-guardrailed-inference/using-hooks-server/nemo-relay).

## Request

This endpoint expects an object with exactly the following fields.
Any other field returns `422`.

<ParamField path="hook_event_name" type="string" required={true}>
The guardrail event, `NemoRelayToolConditionalExecutionGuardrail`.
Any other event returns `422` with the code `unsupported_hook_event`.
</ParamField>

<ParamField path="tool_name" type="string" required={true}>
The tool's name, as NeMo Relay passes it to the guardrail.
The tool policy and per-tool rails match it exactly. Must not be empty.
</ParamField>

<ParamField path="tool_input" type="any" required={true}>
The tool's arguments, as NeMo Relay passes them to the guardrail.
A value that is not a JSON object is denied.
</ParamField>

## Response

An allowed or denied call returns `200` with the following object.

<ParamField path="decision" type="string" required={true}>
`allow` or `deny`.
</ParamField>

<ParamField path="reason" type="string">
Why the call was denied, without a prefix. Present only on a deny.
The reason is the tool policy's reason, such as `tool call 'search' passes 1 argument its allowed_tools entry doesn't list`, or the name of the per-tool rail that blocked the call.
For the reasons, refer to [Deny Reasons](/run-guardrailed-inference/using-hooks-server/results-and-errors#deny-reasons).
</ParamField>

## Errors

Every error uses the OpenAI error envelope, with `message`, `type`, `param`, and `code` in an `error` object.
Map every error status to the guardrail callback's `Err`, never to `Ok(None)`.
The endpoint can return the following errors:

| Status | `code` | When |
|---|---|---|
| `422` | `unsupported_hook_event` | `hook_event_name` is an event other than `NemoRelayToolConditionalExecutionGuardrail`. |
| `422` | `null` | The body is not JSON, or is not a JSON object. `param` is `null`. |
| `422` | `null` | A required field is missing or invalid, or the body has another field. `param` names the field. |
| `500` | `rail_failed` | A per-tool rail failed instead of deciding, for example because its model call failed. |
| `500` | `null` | The check failed for another reason, or the server hit an unexpected error. |
| `503` | `queue_full` | The server's admission queue is full. The response carries `Retry-After: 30`. |

For every error, refer to [Hooks Server Results and Errors](/run-guardrailed-inference/using-hooks-server/results-and-errors#errors).
